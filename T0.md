## 0. Principles

- **One producer, four consumers.** Graph-Ontology produces a T0 **release**. The four tracks only ever read releases.
  No track reads `out/graph.duckdb` while it is being built.
- **A release is immutable.** It is a directory named by its release id, made read-only once written. Nothing is
  edited in place; a correction is a new release.
- **Tracks pin a release.** Each track repo holds a `t0.lock` naming the release id and its content fingerprint, and
  refuses to run against anything else.
- **Licensed content never enters git and never leaves the machine** unless the licence matrix says it may.
  Committable T0 artefacts carry codes, predicates and counts, not licensed names or descriptions.
- **Gates refuse; they don't warn.** Every check in this document has a pass/fail criterion. A release that fails a
  gate is not published.

## 1. Frozen, reproducible snapshots

### 1.1 Why
- **Lock clashes.** DuckDB allows one writer. While `build_edges.py` holds its write lock (a build takes about 7
  minutes), even a `read_only=True` connection from another process fails with
  `IO Error: Could not set lock on file … Conflicting lock is held`. That happened repeatedly on 24 Sep. Tracks
  reading a frozen copy never meet the lock.
- **Reproducibility.** Every result in every track has to trace to an exact graph. The live file changes with every
  build.

### 1.2 What "reproducible" means here
DuckDB database files are **not** byte-stable: the same content can be laid out differently on disk. So a snapshot is
identified by a **content fingerprint**, not a file checksum:

- per table: a SHA-256 over every row, rows ordered by all columns, each row serialised as tab-separated text with
  `NULL` for nulls;
- the release fingerprint: a SHA-256 over the sorted list `table_name<TAB>row_count<TAB>table_sha256`.

**The test:** the same Graph-Ontology commit, built from the same pinned sources with the same DuckDB version,
produces the same release fingerprint.

### 1.3 Procedure

1. **Check the producer is clean.** `git -C $GO_REPO status --porcelain` must be empty. If it isn't, refuse, unless
   `--allow-dirty` is passed, in which case the manifest records `"producer_dirty": true` and the release cannot be
   used for T1 display or T4 serving.
2. **Wait for the build to finish.** Open `GO_GRAPH` read-only, retrying on lock errors every 15 s for up to 30 min.
   Never kill a running build to take a snapshot.
3. **Copy through DuckDB, not the filesystem.** A filesystem copy taken mid-checkpoint can be inconsistent; a
   database-level copy runs inside one read transaction.
4. **Fingerprint** every table of the copy.
5. **Pin the sources**: every input the build reads, as reported by `build_edges.sources()`.
6. **Write `manifest.json`**, name the release directory from the fingerprint, and `chmod -R a-w` it once the other
   stages (§8) complete.

### 1.4 Reference implementation

```python
#!/usr/bin/env python3
"""t0 snapshot: freeze graph.duckdb into a release directory with a content fingerprint and source pins."""
import datetime, hashlib, json, os, pathlib, subprocess, sys, time
import duckdb

GO_REPO = pathlib.Path(os.environ.get("GO_REPO", "~/code/au-medicines-compendium")).expanduser()
GO_GRAPH = pathlib.Path(os.environ.get("GO_GRAPH", GO_REPO / "out/graph.duckdb")).expanduser()
GO_RELEASES = pathlib.Path(os.environ.get("GO_RELEASES", "~/go-releases")).expanduser()


def connect_ro(path, wait_s=1800, every_s=15):
    """Open read-only, waiting out a build's write lock rather than failing."""
    start = time.time()
    while True:
        try:
            return duckdb.connect(str(path), read_only=True)
        except duckdb.IOException as e:
            if "lock" not in str(e).lower() or time.time() - start > wait_s:
                raise
            time.sleep(every_s)


def table_fingerprint(con, table):
    cols = [r[0] for r in con.execute(f"DESCRIBE {table}").fetchall()]
    h, n = hashlib.sha256(), 0
    order = ", ".join(f'"{c}"' for c in cols)
    cur = con.execute(f'SELECT {order} FROM {table} ORDER BY {order}')
    while rows := cur.fetchmany(100_000):
        for row in rows:
            h.update(("\t".join("NULL" if v is None else str(v) for v in row) + "\n").encode())
            n += 1
    return n, h.hexdigest()


def path_pin(p: pathlib.Path):
    """Files: sha256 of content. Directories: sha256 of the sorted (relative path, size) listing."""
    if p.is_file():
        h = hashlib.sha256()
        with p.open("rb") as f:
            while chunk := f.read(1 << 20):
                h.update(chunk)
        return {"kind": "file", "size": p.stat().st_size, "sha256": h.hexdigest()}
    if p.is_dir():
        listing = sorted(f"{q.relative_to(p)}\t{q.stat().st_size}" for q in p.rglob("*") if q.is_file())
        return {"kind": "dir", "files": len(listing), "listing_sha256": hashlib.sha256("\n".join(listing).encode()).hexdigest()}
    return {"kind": "missing"}


def main(allow_dirty=False, vocab_dir=os.path.expanduser("~/code/spine/out/omop-vocab")):
    dirty = subprocess.run(["git", "-C", str(GO_REPO), "status", "--porcelain"], capture_output=True, text=True).stdout.strip()
    if dirty and not allow_dirty:
        sys.exit("REFUSED: Graph-Ontology has uncommitted changes (pass --allow-dirty to record them)")
    commit = subprocess.run(["git", "-C", str(GO_REPO), "rev-parse", "HEAD"], capture_output=True, text=True).stdout.strip()

    GO_RELEASES.mkdir(parents=True, exist_ok=True)
    staging = GO_RELEASES / f".staging-{os.getpid()}"
    staging.mkdir()
    src = connect_ro(GO_GRAPH)
    src.close()                                   # the lock is free; copy within one process
    con = duckdb.connect()
    con.execute("SET memory_limit='3GB'")         # the Mac has 8 GB; DuckDB spills to disk beyond this
    con.execute(f"SET temp_directory='{staging / 'tmp'}'")
    con.execute(f"ATTACH '{GO_GRAPH}' AS src (READ_ONLY)")
    con.execute(f"ATTACH '{staging / 'graph.duckdb'}' AS dst")
    con.execute("COPY FROM DATABASE src TO dst")
    con.execute("DETACH src")
    con.execute("USE dst")
    tables = sorted(r[0] for r in con.execute("SELECT table_name FROM information_schema.tables WHERE table_catalog = 'dst'").fetchall())
    fps = {t: table_fingerprint(con, t) for t in tables}
    release_fp = hashlib.sha256("\n".join(f"{t}\t{n}\t{h}" for t, (n, h) in sorted(fps.items())).encode()).hexdigest()

    sys.path.insert(0, str(GO_REPO / "scripts"))
    from build_edges import sources            # the build's own list of inputs
    pins = {name: {"path": str(p), **path_pin(pathlib.Path(p))} for name, p in sources(vocab_dir).items()}

    release_id = f"GO-{datetime.date.today():%Y%m%d}-{release_fp[:8]}"
    manifest = {
        "release_id": release_id, "created_at": datetime.datetime.now().isoformat(timespec="seconds"),
        "producer": {"repo": str(GO_REPO), "commit": commit, "producer_dirty": bool(dirty)},
        "duckdb_version": duckdb.__version__,
        "fingerprint": {"release_sha256": release_fp, "tables": {t: {"rows": n, "sha256": h} for t, (n, h) in fps.items()}},
        "build_log": con.execute("SELECT family, edges FROM build_log").fetchall(),
        "sources": pins,
    }
    con.close()
    (staging / "manifest.json").write_text(json.dumps(manifest, indent=1) + "\n")
    staging.rename(GO_RELEASES / release_id)
    print(release_id)
```

Notes:
- `table_fingerprint` sorts about 8M edge rows. With `memory_limit='3GB'` DuckDB spills to `temp_directory`; expect
  minutes, not seconds. The temp directory is inside the staging folder and removed with it.
- The fingerprint depends on DuckDB's text rendering of values, so it is comparable **within one DuckDB version**.
  The manifest records the version (1.4.5 on 24 Sep); a version change starts a new fingerprint lineage.

### 1.5 Retention (disk)
The Mac's data volume had **11 GB free (95% used)** on 24 Sep, and `graph.duckdb` is about 342 MB. A release with its
views and exports is roughly 1 GB.
- Keep the **three newest releases** plus **every release named in a track's `t0.lock`**.
- `t0 prune` deletes the others, after printing what it will delete.
- Check free space before snapshotting. Refuse if less than 3 GB would remain.

### 1.6 Gates
| Gate | Criterion |
|---|---|
| S1 | producer clean, or dirtiness recorded |
| S2 | copy completed; table row counts in the copy equal the source |
| S3 | fingerprint written for every table |
| S4 | every source in `build_edges.sources()` pinned; none `missing` unless the build log records it as deliberately skipped (`--allow-missing`) |
| S5 | reproducibility: rebuilding the same commit and sources reproduces the fingerprint. Run on the first release, then monthly |

## 2. The licence matrix

### 2.1 Why
Graph-Ontology combines sources under very different terms: national licences, UMLS, copyright-held reference sets,
open licences. Each track does something different with them: T1 displays content, T2 exports to cloud GPUs, T3 runs
on patient data, T4 serves codes to clients. Every one of those uses has to be permitted by every source it touches.

### 2.2 File and schema
`$GO_T0_CONFIG/licence_matrix.yaml`, one entry per source. Every permission field is one of `yes`, `no`,
`conditional` (with the condition written in `conditions`), or `UNKNOWN`.

### 2.4 What each track needs from the matrix
A track may use a source only if every permission it needs is `yes`, or `conditional` with the condition met.
`UNKNOWN` **blocks**.

| Track | Permissions required, for every source its outputs touch |
|---|---|
| GO-Harness (T1) | `process_local`; `display_to_end_users` for any source whose content is shown |
| GO-HGT (T2) | `process_local`; `process_cloud_private` for any source in an exported view, even ID-only |
| GO-PJI (T3) | `process_local`; `process_cloud_private` if hosted; `display_to_end_users` for anything shown in timelines |
| GO-TS (T4) | `serve_codes_to_clients` and `display_to_end_users` for every served code system; attribution published |

### 2.5 Procedure
1. Create the file with a row for every source in §2.3. Default every permission to `UNKNOWN`.
2. For each source, read the licence text, record `evidence`, fill the permissions and conditions, and sign off
   (`reviewed_by`, `reviewed_on`).
3. `t0 licences check --track <T1|T2|T3|T4>` joins the matrix to the sources behind that track's outputs (through
   `graph_vocabs` and the register's `source` column). It fails listing every blocking `UNKNOWN` or `no`.

### 2.6 Gates
| Gate | Criterion |
|---|---|
| L-1 | every source reported by `build_edges.sources()`, and every `source` value in the edge table, maps to a `source_id` |
| L-2 | no track release proceeds with a blocking `UNKNOWN` or `no` for a permission it needs |
| L-3 | every source with an attribution requirement has its text filled |

## 3. Algebraic properties on every predicate

### 3.1 Why
Once a predicate declares its algebra (functional, symmetric, transitive and so on), a whole class of errors becomes
mechanically detectable, with no human reading. This is layer L1 of the validation plan.

### 3.2 File and schema
`$GO_T0_CONFIG/predicate_properties.yaml`, one entry per predicate that appears in `edge`. On 24 Sep that was **212
predicates**: the 105 authored entries in `reference/graph_predicates.json` plus the `sct:<typeId>` SNOMED attributes
generated by `scripts/graph_register.py`.

```yaml
mondo:exact_match:
  risk_class: structural                # clinical_display | clinical_reasoning | structural
  walk: identity                        # identity | classification | none (same meaning as scripts/completeness.py)
  equivalence: true                     # joins equivalence groups (§5.4) and the consistency check
  one_to_one_vocabs: [MONDO, ORPHA, OMIM, DOID, HP, HGNC, NCBIGENE]   # clique rule applies within these
  functional: false                     # at most one object per subject (optionally per object vocab)
  functional_scope: null                # e.g. per_object_vocab
  inverse_functional: false
  symmetric: true
  inverse_of: null                      # e.g. uberon:has_part for uberon:part_of
  transitive: true
  acyclic: false
  irreflexive: true
  disjoint_with: []
  sssom_predicate: skos:exactMatch      # null = not a mapping; not exported (§6)
  display: true                         # may appear in edge_displayable
  requires_attestation: false           # clinical display needs state = attested
```

Every field is required. `unspecified` is allowed for the algebraic fields, but is **counted** (§3.7), and the goal is
to drive it to zero, clinical predicates first.

### 3.3 Where the values come from
1. **Existing knowledge, first.** `scripts/consistency.py` already defines which predicates are equivalence and which
   vocabularies are one-to-one. `scripts/completeness.py` already defines `walk` (identity, walked both ways;
   classification, walked forward only). Copy those decisions in rather than re-deciding them.
2. **Data-suggested candidates.** `t0 properties suggest` measures, for each predicate:
   - maximum and 99th-percentile objects per subject (candidate `functional`);
   - maximum subjects per object (candidate `inverse_functional`);
   - the share of edges whose reverse exists (candidate `symmetric`);
   - self-loops (candidate `irreflexive`);
   - the presence of cycles (candidate `acyclic`).

   It writes suggestions with the evidence counts.
3. **A person declares.** Suggestions are never adopted automatically. Once declared, a property is enforced from then
   on, and a later violation is a finding.

### 3.4 L0 checks (integrity, on every release)

```sql
-- L0.1 rule zero: every edge has a source and a locator
SELECT predicate, count(*) FROM edge WHERE source IS NULL OR source = '' OR source_locator IS NULL OR source_locator = '' GROUP BY 1;

-- L0.2 contract: subject and object vocabularies within the predicate's registered domain and range
SELECT e.predicate, e.s_vocab, e.o_vocab, count(*)
FROM edge e JOIN predicate p ON p.id = e.predicate
WHERE NOT list_contains(p.subject, e.s_vocab) OR NOT list_contains(p.object, e.o_vocab)
GROUP BY ALL;

-- L0.3 every edge endpoint is a node
SELECT count(*) FROM edge e LEFT JOIN node n ON n.vocab = e.s_vocab AND n.code = e.s_code WHERE n.code IS NULL;
SELECT count(*) FROM edge e LEFT JOIN node n ON n.vocab = e.o_vocab AND n.code = e.o_code WHERE n.code IS NULL;

-- L0.4 tier coherence: a route carries one tier (rejected edges aside)
SELECT predicate, method, source, list(DISTINCT tier) AS tiers
FROM edge WHERE state <> 'rejected'
GROUP BY 1, 2, 3 HAVING count(DISTINCT tier) > 1;

-- L0.5 currency: edges on SNOMED codes that are inactive in the pinned edition (join to the compendium's concept status)
-- (compendium.duckdb: concept_status or the RF2 concept snapshot; see §11 for the 343 known retired-AMT edges)

-- L0.6 separation: no Tier 3 content in the edge table
SELECT count(*) FROM edge WHERE tier = '3';
```

### 3.5 L1 checks (algebra, generated per declared property)

For each predicate `P`, the tool generates the queries for the properties declared `true`:

```sql
-- functional: at most one object per subject (per object vocab when functional_scope = per_object_vocab)
SELECT s_vocab, s_code, o_vocab, count(DISTINCT o_code) AS n
FROM edge WHERE predicate = :P AND state <> 'rejected'
GROUP BY 1, 2, 3 HAVING n > 1;

-- inverse_functional: at most one subject per object
SELECT o_vocab, o_code, count(DISTINCT s_vocab || ':' || s_code) AS n
FROM edge WHERE predicate = :P AND state <> 'rejected'
GROUP BY 1, 2 HAVING n > 1;

-- symmetric: every (a, P, b) has (b, P, a)
SELECT a.s_vocab, a.s_code, a.o_vocab, a.o_code
FROM edge a LEFT JOIN edge b
  ON b.predicate = a.predicate AND b.s_vocab = a.o_vocab AND b.s_code = a.o_code
 AND b.o_vocab = a.s_vocab AND b.o_code = a.s_code
WHERE a.predicate = :P AND a.state <> 'rejected' AND b.s_code IS NULL;

-- inverse_of: every (a, P, b) has (b, Q, a)
SELECT a.s_vocab, a.s_code, a.o_vocab, a.o_code
FROM edge a LEFT JOIN edge b
  ON b.predicate = :Q AND b.s_vocab = a.o_vocab AND b.s_code = a.o_code
 AND b.o_vocab = a.s_vocab AND b.o_code = a.s_code
WHERE a.predicate = :P AND a.state <> 'rejected' AND b.s_code IS NULL;

-- irreflexive: no self-loops
SELECT count(*) FROM edge WHERE predicate = :P AND s_vocab = o_vocab AND s_code = o_code;

-- disjoint_with: no pair carries both P and D
SELECT count(*) FROM edge a JOIN edge b
  ON b.predicate = :D AND a.s_vocab = b.s_vocab AND a.s_code = b.s_code AND a.o_vocab = b.o_vocab AND a.o_code = b.o_code
WHERE a.predicate = :P;
```

`acyclic` is checked in Python, because a recursive SQL query over a large hierarchy is slow:

```python
from collections import defaultdict, deque

def find_cycle_nodes(con, predicate):
    """Kahn's algorithm: nodes left after peeling all zero-in-degree nodes sit on or behind a cycle."""
    edges = con.execute("""SELECT s_vocab || ':' || s_code, o_vocab || ':' || o_code
                           FROM edge WHERE predicate = ? AND state <> 'rejected'""", [predicate]).fetchall()
    out, indeg = defaultdict(list), defaultdict(int)
    for s, o in edges:
        out[s].append(o); indeg[o] += 1; indeg.setdefault(s, 0)
    q = deque(n for n, d in indeg.items() if d == 0)
    while q:
        n = q.popleft()
        for m in out[n]:
            indeg[m] -= 1
            if indeg[m] == 0:
                q.append(m)
    return [n for n, d in indeg.items() if d > 0]
```

### 3.6 The clique rule and the consistency baseline
The clique rule says an equivalence group holding two codes from a one-to-one vocabulary means a wrong edge, or a
duplicate in the source. Graph-Ontology already implements it: `scripts/consistency.py`, with results in
`docs/consistency.md`.

- `t0 consistency` runs `consistency.py` **against the snapshot** (point its database path at the release copy) and
  writes `checks/consistency_summary.json`: conflict counts per vocabulary, the largest cluster size, and the top
  bridges.
- **Gate: a ratchet, not zero.** Existing conflicts are known work in progress. On 24 Sep: 1,207 clusters with two
  MONDO diseases, 90 OMIM, 40 HGNC, 3 NCBI Gene, 122 HPO, 481 DOID, 331 Orphanet; largest cluster 86 codes. A release
  **fails if any count rises** above the previous release without a written reason in `RELEASE.md`. The baseline
  moves down as bridges are fixed.

### 3.7 Gates
| Gate | Criterion |
|---|---|
| A-1 | L0.1–L0.4 and L0.6 return no rows |
| A-2 | L0.5: no *new* retired-code edges beyond the known list |
| A-3 | every declared property's L1 check returns zero violations. A violation fails the release until fixed or the declaration is corrected, with a reason |
| A-4 | consistency ratchet holds (§3.6) |
| A-5 | `unspecified` count reported per risk class; must fall release on release until clinical predicates reach zero |

## 4. The validation register

### 4.1 Why
It is the single place that says, for every route, how far it can be trusted and on what evidence. Every track's
display, training and serving decisions read it.

### 4.2 Grain
A **route** is `(predicate, method, source)` in the edge table. There were **570 routes** on 24 Sep. The
`method_version` is the Graph-Ontology commit that produced the release, until loaders record their own versions.

### 4.3 Schema
`register/route_register.parquet` (and a `.csv` copy carrying no licensed text):

| Column | Type | From |
|---|---|---|
| `route_id` | text | `predicate | method | source`, hashed to 12 hex for a short key |
| `predicate`, `method`, `source` | text | edge table |
| `source_id` | text | licence matrix mapping (§2) |
| `edges` | bigint | count, excluding rejected |
| `edges_rejected` | bigint | count with `state = 'rejected'` |
| `tier` | text | the route's single tier (L0.4 guarantees one) |
| `native_verified` | bool | true once load fidelity passes for this route's source (§4.5) |
| `state_mix` | struct | counts by state |
| `risk_class`, `display`, `requires_attestation` | text / bool | `predicate_properties.yaml` |
| `evidence` | text | path of the hand-check or scoring file (`route_evidence.yaml`, §4.4) |
| `n_read`, `n_correct`, `wilson_lo`, `kappa` | int / float | parsed from the evidence file |
| `l1_violations` | int | §3.5 |
| `consistency_bridges` | int | times this route's edges appear as conflict bridges (§3.6) |
| `l2_est_precision`, `l3_suspect_share`, `l4_pass_rate`, `recall`, `f1`, `ablation_delta` | float | filled by later layers; null until then |
| `measured_on`, `pin`, `next_due` | text | evidence file dates; the release's pins; revalidation trigger |
| `priority` | float | §4.6 |

### 4.4 Linking routes to their evidence
Graph-Ontology's hand-check evidence already exists, but is spread across files: `reference/*_handcheck.json`,
`cache/*/…handcheck…json`, `reference/diagnostic_accuracy_verification.json`, and the pool key in
`cache/umls`. The link from route to file is currently implicit, in code and docs.

1. Create `$GO_T0_CONFIG/route_evidence.yaml`, mapping route patterns to evidence files:
   ```yaml
   - match: {predicate: icd10cm:maps_to}
     evidence: reference/icd10cm_handcheck.json
     parse: handcheck_v1            # parser name: how to read n_read / n_correct from this file's shape
   - match: {predicate: loinc:interpreted_in_finding, method: "shared Component + specimen*"}
     evidence: reference/interprets_handcheck.json
     parse: handcheck_v1
   ```
2. Write one parser per evidence-file shape. Each returns `(n_read, n_correct, kappa|None, measured_on)`.
3. `t0 register` fails if a route with tier `1` or `2` has no evidence entry: a graded tier must point at its
   evidence.

### 4.5 Load fidelity: making native routes `native_verified`
**6.77 million edges are `native`** (the publisher's own statements) and none is yet `native_verified`. For each
native source:

1. **Pin:** release id and checksum, already in the manifest (§1).
2. **Count reconciliation:** the rows the loader selects from the source file equal the edges loaded. Differences
   are listed with their reason (filters applied, retired rows dropped).
3. **Round trip:** draw 80 random native edges of the source (seeded), and trace each back to its exact source row.
   **80/80 required.**
4. **Referential integrity:** L0.3 for that source's edges.

Record the result in `route_evidence.yaml` with `parse: load_fidelity_v1`. Until then, native routes appear in
`edge_displayable` (analyst use) but **not** in `edge_clinical` (§5.1).

### 4.6 Priority and the validation queue
```
priority = risk_weight × log10(edges + 1) × uncertainty
risk_weight  = 3 (clinical_display) | 2 (clinical_reasoning) | 1 (structural)
uncertainty  = 1 − l2_est_precision   when L2 exists, else
               0.5 (ungraded) | 0.2 (native, not yet verified) | 0 (graded 1/2, native_verified)
```
`register/validation_queue.csv` lists routes by priority, with the next action for each: hand check, load fidelity,
top-up (a re-partitioned family needs its sample topped back up to 30), or revalidation due.

### 4.7 Gates
| Gate | Criterion |
|---|---|
| R-1 | every route in `edge` appears in the register |
| R-2 | every Tier 1/2 route has an evidence file that parses, and its Wilson lower bound matches its tier (Tier 1 ≥ 0.99; Tier 2 ≥ 0.80) |
| R-3 | no route with `inadmissible` tier is marked `display: true` |
| R-4 | `route_register.csv` contains no licensed text (only predicates, methods, source names, counts, statistics) |

## 5. Shared views

All views are defined over the frozen `graph.duckdb` (attached read-only) and the register, in
`views/views.duckdb`. They are also materialised to Parquet, so tracks that don't use DuckDB can read them.

```sql
-- views/views.duckdb setup
ATTACH '<release>/graph.duckdb' AS g (READ_ONLY);
CREATE TABLE route_register AS SELECT * FROM read_parquet('<release>/register/route_register.parquet');
```

### 5.1 `edge_displayable` and `edge_clinical`

```sql
CREATE VIEW edge_displayable AS
SELECT e.*, r.route_id, r.risk_class, r.wilson_lo, r.evidence
FROM g.edge e
JOIN route_register r
  ON r.predicate = e.predicate
 AND r.method IS NOT DISTINCT FROM e.method
 AND r.source IS NOT DISTINCT FROM e.source
WHERE e.state <> 'rejected'
  AND r.display
  AND (e.tier IN ('1', '2') OR e.tier = 'native');

CREATE VIEW edge_clinical AS
SELECT d.*
FROM edge_displayable d
JOIN route_register r ON r.route_id = d.route_id
WHERE (d.tier IN ('1', '2') OR (d.tier = 'native' AND r.native_verified))
  AND (NOT r.requires_attestation OR d.state = 'attested');
```

- `edge_displayable` is for **analysts and research views:** graded or native, not rejected, and the predicate is
  displayable.
- `edge_clinical` is for **anything a clinician sees** (T1 clinical mode, T3 timelines shown to clinicians): graded,
  or native *and verified*, and attested where the predicate requires it.
- Excluded from both: `ungraded`, `inadmissible`, `decision`, any Tier 3 content, and rejected edges.

### 5.2 `edge_evidence`
The displayable edges with their evidence unpacked, for citation:

```sql
CREATE VIEW edge_evidence AS
SELECT d.predicate, d.s_vocab, d.s_code, d.o_vocab, d.o_code,
       d.source, d.source_locator, d.method, d.tier, d.state, d.pin, d.wilson_lo, d.evidence AS route_evidence,
       d.attrs->>'$.evidence_level' AS evidence_level,
       TRY_CAST(d.attrs->>'$.lr' AS DOUBLE) AS lr,
       d.attrs->'$.lr_ci' AS lr_ci,
       d.attrs->>'$.population' AS population,
       d.attrs->>'$.setting' AS setting,
       d.attrs
FROM edge_displayable d;
```

### 5.3 `synonym`
Every term for every node, for entity linking (T1, T4) and matching (T3). **Licensed text: local only; never
committed or uploaded unless the licence matrix allows it.**

Schema: `vocab, code, term, term_norm, term_type, lang, preferred, source_id, active`.
- `term_norm` is lower-cased, accent-stripped, with punctuation collapsed to single spaces.
- `term_type` is one of `fsn`, `pt`, `syn`, `long_common`, `short`, `display`, `umls_syn`, `graph_name`.

```sql
ATTACH '<GO_COMPENDIUM>' AS cmp (READ_ONLY);

CREATE TABLE synonym AS
-- SNOMED CT-AU: active descriptions; FSN 900000000000003001, synonym 900000000000013009
SELECT 'SCT' AS vocab, d.conceptId AS code, d.term,
       CASE d.typeId WHEN '900000000000003001' THEN 'fsn' ELSE 'syn' END AS term_type,
       'en-AU' AS lang,
       (d.term = c.pt) AS preferred,
       'snomed_ct_au' AS source_id, TRUE AS active
FROM cmp.dsc d JOIN cmp.concept c ON c.id = d.conceptId
WHERE d.active = '1'
  AND d.id IN (SELECT descId FROM cmp.lang)              -- in the Australian English language reference set
  AND d.conceptId IN (SELECT code FROM g.node WHERE vocab = 'SCT')
UNION ALL
-- every node's graph name, as a fallback for vocabularies without a richer term source
SELECT vocab, code, name, 'graph_name', NULL, TRUE, NULL, TRUE FROM g.node WHERE name IS NOT NULL AND name <> '';
```

Add these sources in the same shape:
- **LOINC:** from the LOINC table (`LOINC_TABLE`): `LONG_COMMON_NAME` → `long_common` (preferred), `SHORTNAME` →
  `short`, `DisplayName` → `display`, for LOINC codes in `node`.
- **UMLS 2026AA:** from `cache/umls/2026AA/mrconso.parquet`, English, not suppressed, for the source abbreviations
  mapped to graph vocabularies (for example `HPO`→HP, `OMIM`→OMIM, `NCI`→NCIT, `MSH`→MESH, `RXNORM`→RXN,
  `ICD10CM`→ICD10CM, `LNC`→LOINC), restricted to codes in `node`, as `umls_syn`. Check the column names as written
  by `scripts/umls_mrconso.py`. Leave out source abbreviations whose own licence is restrictive, and follow the
  loader's lesson: MeSH only through main headings (`MH`) and supplementary names (`NM`), because entry terms mislink.
- Then fill `term_norm` in Python (Unicode NFKD, strip combining marks, lower, collapse non-alphanumerics), and
  de-duplicate on `(vocab, code, term_norm, term_type)`.

Check: every node in `node` has at least one synonym row. Nodes without a name are listed, and are already reported
by the build's "nodes without a name" line.

### 5.4 `equivalence_group`
One group id per set of codes the graph says are the same thing, with a representative code. It is used for merging
in T2's ML view, for entity linking in T1 and T4, and for normalisation in T3.

Schema: `group_id, vocab, code, is_representative, group_size, has_conflict`.

1. **Equivalence edges:** predicates with `equivalence: true` in `predicate_properties.yaml`, from edges that are not
   rejected and not `inadmissible`, and graded or native. This must mirror exactly what `consistency.py` follows, so
   the two agree.
2. **Union-find** over those edges:
   ```python
   def groups(pairs):
       parent = {}
       def find(x):
           parent.setdefault(x, x)
           while parent[x] != x:
               parent[x] = parent[parent[x]]
               x = parent[x]
           return x
       for a, b in pairs:
           ra, rb = find(a), find(b)
           if ra != rb:
               parent[max(ra, rb)] = min(ra, rb)
       out = {}
       for x in parent:
           out.setdefault(find(x), []).append(x)
       return out
   ```
3. **Representative:** the first code in the group by `representative_priority` (configured in
   `$GO_T0_CONFIG/t0.yaml`, for example `[SCT, LOINC, RXN, MONDO, HP, ORPHA, OMIM, NCBIGENE, HGNC, UMLS]`), then the
   lowest code.
4. **`has_conflict`:** true if the group holds two codes of a one-to-one vocabulary (§3.6). Tracks must not merge a
   conflicting group blindly: T2 excludes those groups from merging, and T1 and T4 flag them.

### 5.5 Gates
| Gate | Criterion |
|---|---|
| V-1 | `edge_clinical` ⊆ `edge_displayable` ⊆ `edge` |
| V-2 | no row in either view has tier `ungraded`, `inadmissible`, `decision` or `3`, or state `rejected` |
| V-3 | every node has at least one synonym |
| V-4 | equivalence-group conflict counts equal `consistency.py`'s on the same snapshot |
| V-5 | Parquet materialisations match their views' row counts |

## 6. The SSSOM export

### 6.1 Why
SSSOM is the standard exchange format for mappings. Exporting Graph-Ontology's mappings in it lets T4 generate FHIR
ConceptMaps, lets external tools (sssom-py, SeMRA, Boomer) check the mappings, and makes every mapping portable with
its justification and confidence.

### 6.2 Which edges
Predicates with a non-null `sssom_predicate` in `predicate_properties.yaml`. The default correspondence below is
deliberately conservative; the owner confirms each one:

| Graph-Ontology predicate family | `predicate_id` |
|---|---|
| exact identity: `mondo:exact_match`, `umls:shared_cui` (hand-checked families), Orphanet exact alignment | `skos:exactMatch` |
| `omop:maps_to`, `icd10cm:maps_to`, `std_ingredient` | `skos:closeMatch` (a map to a standard concept can be broader) |
| `sct:au_nearest_ancestor` | `skos:broadMatch` |
| `uberon:sct_narrow_match`, `uberon:ncit_narrow_match` | `skos:narrowMatch` |
| classifications: `in_atc_class`, `ccsr:category`, `sct:icd10_map`, `sct:icd10cm_map` | `skos:broadMatch` |
| cross-references of uncertain strength: `drugcentral:xref`, `hp:xref` | `skos:relatedMatch` |

### 6.3 Columns

| SSSOM column | Filled from |
|---|---|
| `subject_id`, `object_id` | CURIEs from the curie map (§6.4) |
| `subject_label`, `object_label` | `node.name`, **full export only** |
| `predicate_id` | §6.2 |
| `mapping_justification` | from the route: hand-checked → `semapv:ManualMappingCuration`; name-based → `semapv:LexicalMatching`; chain rules → `semapv:MappingChaining`; the source's own asserted map → `semapv:UnspecifiedMatching`, with the source recorded in `mapping_provider` |
| `confidence` | the route's Wilson lower bound for Tier 1/2; empty otherwise (confidence is **earned**, never declared) |
| `mapping_tool` | `build_edges.py@<commit>` |
| `mapping_date` | release date |
| `subject_source_version`, `object_source_version` | pins from the manifest |
| `mapping_provider` | the edge's `source` |
| `comment` | the edge's `method` |
| extension columns | `go_route_id`, `go_tier`, `go_state`, `go_source_locator`, `go_pin`, declared in the metadata file as SSSOM extension definitions |

## 7. The quiz suite

### 7.1 Why
The quiz suite is layer L4 of the validation plan: regression tests with expected answers, run on every release. It
blocks a release when a known-false fact reappears, and it gives each track a fixed yardstick. The same items serve
T1 (answers), T2 (ranking and held-out links), T3 (normalisation) and T4 (translation and matching).

### 7.2 Files
`$GO_T0_CONFIG/quiz/items/<domain>.yaml`, versioned with the config. One item:

```yaml
- id: pbs-0001
  version: 1
  tracks: [T1, T4]
  kind: competency              # competency | known_negative | held_out | abstention | adversarial
  query:
    type: neighbors             # lookup | neighbors | path | subsumes | translate | match | harness_nl
    params: {system: SCT, code: "<code>", predicates: [pbs:lists], min_tier: "2"}
  expected:
    category: TopAnswer         # TopAnswer | Acceptable | BadButForgivable | NeverShow
    answers: [{system: PBS_ITEM, code: "<code>"}]
    k: 10
  rationale: "<why this is the right answer, with its source>"
  source: "<person or evidence file>"
  created: 2026-09-24
```

### 7.3 Query types
The deterministic types run straight against the release views. `match` and `harness_nl` need a track's service.

| Type | Runs against | Result, as a ranked list |
|---|---|---|
| `lookup` | `node` + `synonym` | the node and its preferred term |
| `neighbors` | `edge_displayable` (or `edge_clinical` with `clinical: true`) | objects, ranked by tier, then Wilson lower bound, then code |
| `path` | `edge_displayable`, at most 3 hops | end nodes of paths, shortest first |
| `subsumes` | the is-a closure | true or false |
| `translate` | equivalence groups and mapping edges | target codes |
| `match` | T4's `/match` | candidate codes |
| `harness_nl` | T1's harness | the cited edge ids and the codes they contain |

### 7.4 Where items come from
1. **Competency items,** written by a domain expert. At least 20 in each starting domain: medicines and PBS;
   pathology, LOINC and units; conditions and the SNOMED hierarchy; cross-vocabulary mapping; diagnostic likelihood
   ratios.
2. **Known negatives, generated automatically:** every edge with `state = 'rejected'` (201 on 24 Sep) and every
   hand-check `wrong` verdict becomes a `NeverShow` item: `neighbors(s, predicate)` must not contain `o`. The 26
   hand-checked consistency bridges that were rejected are included this way.
3. **Held-out links:** each release draws a seeded 1% sample of graded edges per target relation into
   `quiz/held_out.parquet`. T2 removes them before training and measures how highly it ranks them. The seed is the
   release fingerprint, so the sample is reproducible.
4. **Abstention items:** questions the graph cannot answer (for example diagnosis posteriors while priors are
   `needs_source`). The expected result is an empty list, or an abstention from a service.
5. **Adversarial items** (T1): prompts designed to extract unsupported numbers or override rules.

### 7.5 Scoring

| Category | Passes when |
|---|---|
| `TopAnswer` | an expected answer ranks within `k` (default 10) |
| `Acceptable` | an expected answer ranks within 50 |
| `BadButForgivable` | the listed answer is not within `k` |
| `NeverShow` | the listed answer is **absent entirely**. One failure fails the release |
| abstention | the result is empty, or the service abstains |

Report the pass rate per domain and per kind, with Wilson intervals. For held-out links, report mean reciprocal rank
and Hits@10.

### 7.6 Results and gates
`quiz/results.json` records the release id, suite version, per-item outcomes, and summary rates.

| Gate | Criterion |
|---|---|
| Q-1 | **zero NeverShow failures** |
| Q-2 | each domain's pass rate is not lower than the previous release beyond its Wilson interval, unless `RELEASE.md` explains the drop |
| Q-3 | every `wrong` verdict and rejected edge since the last release has a NeverShow item |

## 8. The release procedure

Run in this order. Any failed gate stops the run; the staging directory is kept for diagnosis and never published.

| Step | Command (to be built, §10) | Produces | Gates |
|---|---|---|---|
| 1 | `t0 snapshot` | `graph.duckdb`, `manifest.json` | S1–S4 |
| 2 | `t0 licences check` | licence section of `RELEASE.md` | L-1, L-3 (L-2 runs per track) |
| 3 | `t0 checks` | `checks/l0_l1_report.json` | A-1 to A-3, A-5 |
| 4 | `t0 consistency` | `checks/consistency_summary.json` | A-4 |
| 5 | `t0 register` | `register/*` | R-1 to R-4 |
| 6 | `t0 views` | `views/*` | V-1 to V-5 |
| 7 | `t0 sssom` | `sssom/*` | M-1 to M-4 |
| 8 | `t0 quiz` | `quiz/*` | Q-1 to Q-3 |
| 9 | `t0 release` | `RELEASE.md`; directory made read-only; `latest` symlink updated | all of the above |

`RELEASE.md` holds:
- the release id and fingerprint;
- the producer commit;
- counts: nodes, edges, edges by tier and state, routes;
- every gate's result;
- the consistency ratchet, compared with the previous release;
- quiz rates;
- the licence blockers per track;
- a diff against the previous release: routes added or removed, edge counts changed by more than 1%, and tiers
  changed.

**Cadence:** a release after every Graph-Ontology merge that changes the graph, and always after a source-pin change
(the monthly SNOMED CT-AU and PBS releases, LOINC twice a year).

## 9. How a track consumes a release

1. **Pin it.** Commit `t0.lock` in the track repo:
   ```yaml
   release_id: GO-20260924-1a2b3c4d
   release_sha256: <full fingerprint from manifest.json>
   releases_dir: ~/go-releases        # overridable with GO_RELEASES
   ```
2. **Verify on start.** Read `manifest.json`, compare `release_sha256`, and refuse on mismatch. Recomputing the full
   fingerprint is optional; comparing the manifest is enough day to day, because the directory is read-only.
3. **Open read-only.** `duckdb.connect('<release>/graph.duckdb', read_only=True)`, or attach `views/views.duckdb`.
   Never write into a release.
4. **Check licences for the track.** `t0 licences check --track <T>` must pass before any track output leaves the
   machine or reaches a user.
5. **Record the release id in every output:** metrics, served responses, harness traces, ETL run manifests.
6. **Upgrade deliberately.** Bump `t0.lock` in a pull request that includes the release diff and the track's own
   regression results on the new release.

| T0 element | GO-Harness (T1) | GO-HGT (T2) | GO-PJI (T3) | GO-TS (T4) |
|---|---|---|---|---|
| Snapshot | reads | exports the ML view from it | normalises against it | loads from it |
| Licence matrix | display | cloud export | hosting, display | serving, attribution |
| Predicate properties | display flags, risk classes | merge rules (`equivalence`), leakage candidates | subsumption for dedup | ConceptMap equivalence semantics |
| Register | tier shown with each claim | tier filter for the view; ablation Δ written back | mapping tier per event | clinical vs candidate ConceptMaps |
| `edge_displayable` / `edge_clinical` | the only edges it may cite | default training edges | concept links | translation sources |
| `synonym` | entity linking | (not used: names never leave) | matching source text | the `/match` index |
| `equivalence_group` | expands concepts before querying | merges nodes (conflicting groups excluded) | normalisation to a representative | `$translate` equivalence |
| SSSOM export | — | — | — | ConceptMap generation |
| Quiz suite | answers, abstention, NeverShow | held-out ranking; harness A/B | normalisation items | translation and matching items |

## 10. Building the T0 tooling

### 10.1 Where it lives
**Recommended:** in Graph-Ontology, as `scripts/t0/` with a `t0` entry point, plus the configuration in `t0/` at the
repo root. T0 reads Graph-Ontology's internals (`build_edges.sources()`, `consistency.py`, the compendium database), so
the producer belongs next to them. The track repos carry this document and their `t0.lock`. (Decision T0-D1, §12.)

### 10.2 Build order and effort

| # | Piece | Depends on | Rough effort |
|---|---|---|---|
| 1 | `t0 snapshot` and `t0 prune` | — | ½ day |
| 2 | `licence_matrix.yaml` skeleton and `t0 licences check` | 1 | ½ day of code; the review itself is separate and per source |
| 3 | `predicate_properties.yaml` seeded from `consistency.py` and `completeness.py`; `t0 properties suggest`; `t0 checks` | 1 | 1–2 days, then ongoing declarations |

### 10.3 Acceptance test for the tooling itself
- Two releases from the same commit and pins have the same fingerprint.
- Deliberately injected faults are each caught by the right gate:
  - an edge with no source;
  - an edge whose vocabulary is outside its predicate's range;
  - a route with two tiers;
  - a functional violation on a predicate declared functional;
  - a new MONDO–MONDO conflict;
  - a rejected edge reappearing in `edge_displayable`;
  - a NeverShow answer reappearing.
- A track with a blocking `UNKNOWN` in the licence matrix fails `t0 licences check`.
